# 日志开关与回归验证

`设置 → 外观 → 日志 → 启用日志文件` 控制全部应用日志，包括页面导航、网易云诊断和异常记录。修改立即影响新日志，并通过现有设置机制保存，重启后继续使用。

实现约定：

- 业务代码统一调用 `AppLog.Info / Warning / Error`，仅在包装层调用底层文件日志库。
- 在共同写入入口检查开关，关闭时不初始化文件日志库、不提交新记录。旧版 `*Always` 方法仅作为兼容别名，也遵守开关。
- 每个进程只加载一次日志偏好；用户操作更新线程同步保护下的内存状态并保存，避免每条日志读取 XML。
- 外观页在绑定前取得日志状态，异步加载其他设置不能覆盖用户刚改变的日志开关。
- 禁用不删除已有日志。底层日志库异步写入，关闭前已排队的记录可能短暂继续落盘；新进程以禁用状态启动不会创建日志目录或文件。
- 文件名、方法名和行号保持正确传递；日志或配置访问异常不能向调用方传播。

在 Windows PowerShell 7 中运行：

```powershell
pwsh -NoProfile -File .\tools\LoggingRegression\Test-Logging.ps1
```

测试使用 Windows 自带的 .NET Framework C# 编译器，仅编译日志与设置相关源码，并加载仓库中的真实 `Digimezzo.Foundation.Core.dll`。每次运行创建独立临时目录与测试配置，不读取或修改用户的播放器配置。结束后清理该目录。

覆盖：禁用启动时六个入口均不创建日志、开启后所有级别及调用位置正确、运行中关闭后新消息不追加、其他设置保存时保留关闭状态、独立新进程恢复关闭状态、配置缺失时不向调用方抛异常。

可用 `-SourceRevision <commit>` 验证旧版源码；修复前的源码应在“禁用时仍创建日志”断言失败。该测试属于独立组件运行验证，不代表完整 WPF 应用已构建或完成界面验证。
