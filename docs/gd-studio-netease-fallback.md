# 网易云的 GD Studio 备用音源

网易云推荐，以及“在线搜索”中来源为 `netease` 的歌曲，共用以下取址顺序：

1. 网易云官方音源。
2. 官方返回仅试听、版权限制、会员限制或空地址时，尝试 GD音乐台（music.gdstudio.xyz）。
3. GD 无法取得地址时，尝试已启用的 UnblockNeteaseMusic。

GD 备用音源自动参与上述链路，不依赖 UnblockNeteaseMusic 开关。官方成功时不会请求 GD。账号未登录、会话失效、网络异常、限流和取消不会被当成音源权限问题处理。

## 请求与身份

使用 `https://music-api.gdstudio.xyz/api.php?types=url&source=netease&id=<歌曲ID>&br=320`，沿用原始网易云歌曲 ID，不通过歌名搜索匹配。在线搜索结果即使缺少时长也可以使用这个备用音源。歌曲队列身份仍为 `netease://song/<ID>`，收藏、歌词和推荐信息继续使用网易云身份。

备用播放请求 320K，实际音质以服务返回为准。它不使用“在线搜索下载与播放音质”选项，也不尝试逐档重复请求。GD 客户端不使用 Cookie，与网易云认证客户端独立。

## 请求控制

- 搜索、图片、下载和备用取址复用同一个 GD 客户端，合计最多 50 次请求 / 任意连续 5 分钟。
- 保留 1.2 秒的最小间隔。额度耗尽时立即返回限流结果，不等待数分钟阻塞当前播放。
- HTTP 429 尊重 `Retry-After`，缺失时冷却 5 分钟。
- 备用提供器缓存成功地址 60 秒、普通失败 10 秒，最多 128 首，合并同一提供器内的并发请求。限流与取消不写入该缓存。
- 强制刷新先丢弃旧地址，再重新取址；取消后不继续尝试下一提供器。

缓存的音频沿用现有临时缓存，键包含 `gdstudio-netease` 和音质，避免与官方音源或其他提供器混用。音频缓存或解码失败时沿用现有的一次强制刷新规则；取得 GD 地址后发生的下载失败，不代表已执行跨提供器切换。

## 可观察性与范围

日志记录提供器、歌曲 ID、官方失败原因、备用取址结果和失败代码，不打印播放 URL、Cookie 或响应正文。所有日志遵守“启用日志文件”开关。歌曲信息页显示实际备用音源来源。

“官方优先”的下载与歌曲信息查询也复用这个备用链路。显式“UnblockNeteaseMusic 优先”的下载策略保持原有行为，不会让 GD 抢在 Unblock 前取址。

## 文档与实测差异

API 文档将 `size` 标为 KB。2026-10-07 对网易云歌曲 `526081111` 的实测返回 `size=8837805`，音频 HEAD 的 `Content-Length` 同为 `8837805`，类型为 `audio/mpeg`。当前模型按字节保存；740/999 是音质档位，不当作真实 kbps。接口成功及 HEAD 成功不等于完整播放验证，也不保证每首歌曲可用。

## 验证

`GdMusicAudioFallbackTests` 覆盖精确 ID、无时长结果、缓存、强制刷新、并发、取消与 URL 校验；`GdMusicRequestBudgetTests` 覆盖滚动窗口及冷却；`NeteaseFallbackPipelineTests` 覆盖官方优先、备用顺序、失败原因保留与取消传播。这些测试已加入现有 NUnit 项目，由 GitHub Actions 编译并执行。完整应用构建及打包以 `Build Portable` 的结果为准。
